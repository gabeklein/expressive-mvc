How Expressive relates to the store libraries you already know. For the case against raw hooks, see [Why Classes?](/docs/why-classes) - this page is about the libraries you'd otherwise pick instead.

Every library makes a single counter short, so a lone widget proves little. The fair test is a feature that splits: one owner, several views, each re-rendering only for what it reads. Below, the views' markup is held identical - only the cost of the owner and the wiring differs.

<br />

## One feature, two views

A player owns a track and a play state. `Title` shows the track; `Toggle` plays and pauses. Pausing should not re-render `Title`. Flip through:

<Compare labels={['Expressive', 'Hooks', 'Zustand', 'Jotai', 'Redux', 'MobX']}>

```tsx
import { Component } from '@expressive/mvc';

class Player extends Component {
  track = 'Intro';
  playing = false;

  toggle() {
    this.playing = !this.playing;
  }

  render() {
    return (
      <>
        <Title />
        <Toggle />
      </>
    );
  }
}

function Title() {
  const { track } = Player.get();

  return <h2>{track}</h2>;
}

function Toggle() {
  const { playing, toggle } = Player.get();

  return <button onClick={toggle}>{playing ? 'Pause' : 'Play'}</button>;
}
```

```tsx
import { createContext, useContext, useState } from 'react';

const PlayerContext = createContext<{
  track: string;
  playing: boolean;
  toggle: () => void;
} | null>(null);

function usePlayer() {
  const player = useContext(PlayerContext);

  if (!player)
    throw new Error('Player missing');

  return player;
}

function Player() {
  const [playing, setPlaying] = useState(false);
  const toggle = () => setPlaying(p => !p);

  return (
    <PlayerContext.Provider value={{ track: 'Intro', playing, toggle }}>
      <Title />
      <Toggle />
    </PlayerContext.Provider>
  );
}

function Title() {
  const { track } = usePlayer();

  return <h2>{track}</h2>;
}

function Toggle() {
  const { playing, toggle } = usePlayer();

  return <button onClick={toggle}>{playing ? 'Pause' : 'Play'}</button>;
}

// every consumer re-renders on any change
```

```tsx
import { createContext, useContext, useState } from 'react';
import { createStore, useStore, type StoreApi } from 'zustand';

type PlayerState = { track: string; playing: boolean; toggle(): void };

const makePlayer = () => createStore<PlayerState>(set => ({
  track: 'Intro',
  playing: false,
  toggle: () => set(s => ({ playing: !s.playing })),
}));

const PlayerContext = createContext<StoreApi<PlayerState> | null>(null);

function usePlayer<T>(select: (s: PlayerState) => T) {
  const store = useContext(PlayerContext);

  if (!store)
    throw new Error('Player missing');

  return useStore(store, select);
}

function Player() {
  const [store] = useState(makePlayer);

  return (
    <PlayerContext.Provider value={store}>
      <Title />
      <Toggle />
    </PlayerContext.Provider>
  );
}

function Title() {
  const track = usePlayer(s => s.track);

  return <h2>{track}</h2>;
}

function Toggle() {
  const playing = usePlayer(s => s.playing);
  const toggle = usePlayer(s => s.toggle);

  return <button onClick={toggle}>{playing ? 'Pause' : 'Play'}</button>;
}
```

```tsx
import { atom, createStore, Provider, useAtom, useAtomValue } from 'jotai';
import { useState } from 'react';

const trackAtom = atom('Intro');
const playingAtom = atom(false);

function Player() {
  const [store] = useState(() => createStore());

  return (
    <Provider store={store}>
      <Title />
      <Toggle />
    </Provider>
  );
}

function Title() {
  const track = useAtomValue(trackAtom);

  return <h2>{track}</h2>;
}

function Toggle() {
  const [playing, setPlaying] = useAtom(playingAtom);
  const toggle = () => setPlaying(p => !p);

  return <button onClick={toggle}>{playing ? 'Pause' : 'Play'}</button>;
}

// the Provider scopes every atom in the subtree
// to this store, not just the player's
```

```tsx
import { configureStore, createSlice } from '@reduxjs/toolkit';
import { Provider, useDispatch, useSelector } from 'react-redux';
import { useState } from 'react';

const player = createSlice({
  name: 'player',
  initialState: { track: 'Intro', playing: false },
  reducers: {
    toggle: (s) => { s.playing = !s.playing; },
  },
});

type State = ReturnType<typeof player.reducer>;

function Player() {
  const [store] = useState(() =>
    configureStore({ reducer: player.reducer }));

  return (
    <Provider store={store}>
      <Title />
      <Toggle />
    </Provider>
  );
}

function Title() {
  const track = useSelector((s: State) => s.track);

  return <h2>{track}</h2>;
}

function Toggle() {
  const playing = useSelector((s: State) => s.playing);
  const dispatch = useDispatch();
  const toggle = () => dispatch(player.actions.toggle());

  return <button onClick={toggle}>{playing ? 'Pause' : 'Play'}</button>;
}
```

```tsx
import { makeAutoObservable } from 'mobx';
import { observer } from 'mobx-react-lite';
import { createContext, useContext, useState } from 'react';

class PlayerState {
  track = 'Intro';
  playing = false;

  constructor() {
    makeAutoObservable(this, {}, { autoBind: true });
  }

  toggle() {
    this.playing = !this.playing;
  }
}

const PlayerContext = createContext<PlayerState | null>(null);

function usePlayer() {
  const player = useContext(PlayerContext);

  if (!player)
    throw new Error('Player missing');

  return player;
}

function Player() {
  const [state] = useState(() => new PlayerState());

  return (
    <PlayerContext.Provider value={state}>
      <Title />
      <Toggle />
    </PlayerContext.Provider>
  );
}

const Title = observer(() => {
  const { track } = usePlayer();

  return <h2>{track}</h2>;
});

const Toggle = observer(() => {
  const { playing, toggle } = usePlayer();

  return <button onClick={toggle}>{playing ? 'Pause' : 'Play'}</button>;
});
```

</Compare>

Every other tab builds the same three things by hand: a per-instance store, a context to carry it, and a typed hook to read it back - then each view declares what it reads, through a selector or a wrapper. In Expressive the Component is all three. It owns the instance, provides itself to whatever it renders, and `Player.get()` is the typed hook. Destructuring is the selector: `Title` re-renders when `track` changes, not when `playing` does.

Growing the feature changes nothing about the owner - another view is another function calling `Player.get()`. And the fields are typed props: `<Player track="Verse" />`.

<br />

## Shared state

Context is where store libraries quietly hand the problem back to you. In Expressive, your classes themselves are context keys - anything needing `Theme` just asks for it: another instance via `get(Theme)`, a component via `Theme.get()`.

<Compare labels={['Expressive', 'React Context', 'Zustand', 'Jotai']}>

```tsx
import { Model, get } from '@expressive/mvc';

class Theme extends Model {
  mode = 'light';

  toggle() {
    this.mode = this.mode === 'light' ? 'dark' : 'light';
  }
}

class Panel extends Model {
  theme = get(Theme);

  get dark() {
    return this.theme.mode === 'dark';
  }
}

function ModeBadge() {
  const { mode, toggle } = Theme.get();

  return <button onClick={toggle}>{mode}</button>;
}
```

```tsx
import { createContext, useContext, useState } from 'react';

const ThemeContext = createContext<{
  mode: string;
  toggle: () => void;
} | null>(null);

function ThemeProvider({ children }) {
  const [mode, setMode] = useState('light');

  const toggle = () =>
    setMode(m => (m === 'light' ? 'dark' : 'light'));

  return (
    <ThemeContext.Provider value={{ mode, toggle }}>
      {children}
    </ThemeContext.Provider>
  );
}

function ModeBadge() {
  const theme = useContext(ThemeContext);

  if (!theme)
    throw new Error('ThemeProvider missing');

  return <button onClick={theme.toggle}>{theme.mode}</button>;
}
```

```tsx
import { createContext, useContext, useState } from 'react';
import { createStore, useStore } from 'zustand';

const ThemeContext = createContext(null);

const makeTheme = () => createStore(set => ({
  mode: 'light',
  toggle: () => set(s =>
    ({ mode: s.mode === 'light' ? 'dark' : 'light' })),
}));

function ThemeProvider({ children }) {
  const [store] = useState(makeTheme);

  return (
    <ThemeContext.Provider value={store}>
      {children}
    </ThemeContext.Provider>
  );
}

function ModeBadge() {
  const store = useContext(ThemeContext);

  if (!store)
    throw new Error('ThemeProvider missing');

  const { mode, toggle } = useStore(store);

  return <button onClick={toggle}>{mode}</button>;
}
```

```tsx
import { atom, createStore, Provider, useAtom } from 'jotai';
import { useState } from 'react';

const modeAtom = atom('light');

function ThemeProvider({ children }) {
  const [store] = useState(() => createStore());

  return (
    <Provider store={store}>
      {children}
    </Provider>
  );
}

function ModeBadge() {
  const [mode, setMode] = useAtom(modeAtom);

  const toggle = () =>
    setMode(m => (m === 'light' ? 'dark' : 'light'));

  return <button onClick={toggle}>{mode}</button>;
}

// note: the Provider scopes every atom in the
// subtree to this store, not just the theme
```

</Compare>

No `createContext<T>`, no null default, no missing-provider guard, no Provider/Consumer pair to keep in sync. Every library lands back here eventually - Zustand has you wrap a store in React context yourself, Jotai's Provider scopes a whole atom store, MobX leaves it to you entirely.

<br />

## vs Zustand

Zustand is a great lightweight store. The differences that matter in practice:

- **Destructuring is the selector** - no per-access selector functions or shallow-compare helpers.
- **Classes are the organizational unit** - no factory functions, no spread-based updates.
- **One API for every scope** - the same class can back a global store, a per-component instance, or a provider tree.
- **Lifecycle is built in** - `new()`/`mount()` and automatic destruction replace manual subscribe/teardown.

<br />

## vs Redux (and RTK)

Redux introduces actions, reducers, selectors, and a dispatch indirection. Expressive collapses all four into methods:

```tsx
class Counter extends Model {
  count = 0;

  increment() {
    this.count++;
  }
}
```

- Updates: direct assignment instead of `dispatch(action)`.
- Subscription: destructure instead of `useSelector`.
- Async: regular async methods instead of thunks or sagas.
- Composition: class inheritance instead of store merging.

> Redux's time-travel devtools are real value. If you rely on them daily, factor that in - Expressive gives you plain objects and standard browser debugging instead.

<br />

## vs MobX

MobX is the closest relative - both use observable objects with automatic dependency tracking. Expressive is what you get when that idea is allowed to own the whole problem:

- **No `observer()` wrapper.** Miss one in MobX and you get stale renders. Expressive tracks through `render()` and `get()` themselves.
- **No `makeAutoObservable`.** Extending `Model` is enough - and methods arrive pre-bound.
- **Lifecycle, context, and Suspense are built in** - `new()`/`mount()`, class-keyed context, async `set()`. In MobX these are pieces you wire together yourself.

If you like MobX, you'll feel at home here. Expressive is simply more opinionated about the parts MobX leaves as an exercise.

<br />

## When not to use Expressive

- Your team has a strict "functional only" code style.
- Your app is mostly server-rendered with minimal client state.
- You already have a state solution that works and causes no pain.
- You rely heavily on Redux devtools' time-travel debugging.

Expressive is a tool for a specific kind of complexity. If you don't have it, you don't need it.

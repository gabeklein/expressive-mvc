title: React Hooks
description: Model.get, providing context, and Model.use for adopting classes into hook-style components
---

The React adapter augments the `Model` class with two static hooks. `Model.get()` is the everyday one - function components read state that a Component owns or an element provides. `Model.use()` is the on-ramp - it lets a hook-style function component own an instance while you adopt classes. Import the adapter once, for its side effect, in your app's entry; everything else imports from `@expressive/mvc`.

```tsx
import '@expressive/react';
import { Model, Component } from '@expressive/mvc';
```

<br />

## `Model.get()`

Fetches an instance from context and subscribes to accessed properties.

```tsx
function Profile() {
  const { user } = UserProfile.get();
  return <h1>{user.name}</h1>;
}
```

- Throws `Could not find UserProfile in context.` if the instance is not provided above.
- Re-subscribes (and refreshes) if the upstream instance is replaced.

### Optional lookup

```tsx
const maybe = Theme.get(false); // Theme | undefined
```

### Required values

```tsx
const user = User.get(true); // Required<User>
```

With `true`, reading a property that is currently `undefined` throws a plain `Error` - `User-XXXXXX.name is required in this context.` That surfaces at the nearest **error boundary**, not Suspense. Use it when the component's contract is "this data exists by now."

### Computed selector

Pass a factory to derive a value. The component re-renders only when the derived result changes by `===`:

```tsx
const summary = Cart.get((cart) => ({
  total: cart.total,
  count: cart.count
}));
```

The factory receives:

- A tracking proxy (reads subscribe).
- A `ForceRefresh` function.

### Effect mode

Return `null` from the factory to run a side effect once, on first render, without subscribing - the factory doesn't run again:

```tsx
AppState.get((app) => {
  analytics.track('page', app.page);
  return null;
});
```

### `ForceRefresh`

The second argument is a function that forces the component to re-render:

```ts
type ForceRefresh = {
  (): void;
  <T>(waitFor: Promise<T>): Promise<T>;
  <T>(invoke: () => Promise<T>): Promise<T>;
};
```

```tsx
const data = DataService.get((svc, refresh) => {
  const reload = () => refresh(svc.fetch());
  return { items: svc.items, reload };
});
```

Given a promise (or async function), it refreshes now and again when the promise settles.

## Providing context

Hooks read what an ancestor provides. Provide an instance with the bare `Component` class:

```tsx
<Component for={Theme} color="dark">
  <App />
</Component>
```

- A class is constructed and owned by the element, destroyed on unmount; `is` receives it.
- An instance someone else owns - a Component's field, a module-scope `Model.new()` - is provided as-is and never destroyed by the element.
- Other attributes are typed from the instance and assigned to it on every render.
- `fallback` adds a Suspense boundary and `catch` an error boundary; without them it adds none.
- One instance per element - several belong to a parent instance owning them as fields.

`Provider` was removed in favor of `<Component for>`. Its record form (`for={{ theme: Theme, auth: Auth }}`) has no equivalent - compose a parent `Model` class instead. Details in the [Context guide](/docs/guides/context#providing-with-component-for).

<br />

## Reading context inline

`Consumer` was removed. Read context with `Model.get()` in a small function component:

```tsx
const Themed = () => {
  const theme = Theme.get();
  return <p style={{ color: theme.color }}>Themed</p>;
};
```

## `Model.use(...args)`

Creates an instance owned by the calling function component.

```tsx
function CounterView() {
  const { count, increment } = Counter.use();
  return <button onClick={increment}>{count}</button>;
}
```

This is not the default way to own state. When state belongs to one view, make that view a [`Component`](/docs/api/component) - the class owns its fields and renders itself, and fields double as props. When state is shared, place it with [`<Component for>`](#providing-context) and read it with `Model.get()`. Function components then stay stateless projections of state that lives in classes.

`Model.use()` earns its place in two cases:

- **Adopting incrementally.** Swap a component's tangle of `useState` and `useEffect` for one class without restructuring the component - see [Migrating from Hooks](/docs/migrating-from-hooks). Moving the JSX into a `Component` is the usual next step.
- **Exporting a hook.** A library whose public API is a hook can implement it as `const useCart = () => Cart.use();`.

Behavior:

- Instance is created on mount and destroyed on unmount.
- Reading properties subscribes the component - it re-renders when those properties change.
- Methods are auto-bound; safe to destructure and pass as event handlers.
- Strict mode safe (handles double-mount correctly).
- An instance is not kept by a render React discards. If the component suspends before its first commit - including on the instance's own pending value - each retry creates and loads a new one, and the render never resolves. Own loading state above the reader: a `Component`, which is its own Suspense boundary, or `<Component for>` with a `fallback`.
- A `Component` subclass can't be used this way - `MyComponent.use()` throws. Render it instead.

### With initial values

```tsx
const form = Form.use({ name: 'Alice', email: 'a@b.c' });
```

### With a lifecycle callback

```tsx
const timer = Timer.use((self) => {
  self.start();
  return () => self.stop();
});
```

### With a `use()` method

If your class defines a `use()` method, its parameters define the arguments to `Model.use()`:

```tsx
class Search extends Model {
  query = '';

  use(props: { initialQuery: string }) {
    this.query = props.initialQuery;
  }
}

const state = Search.use({ initialQuery: 'react' });
```

`use()` runs on every render, so it can also call React hooks:

```tsx
class Nav extends Model {
  path = '/';

  use() {
    this.path = useLocation().pathname;
  }
}
```

Both jobs have a Component form. Per-render arguments are fields passed as props (`<Search query="react" />`), with anything derived from them as getters. Third-party hooks are read in an outer function that passes props, or called at the top of `render()`, which runs as a real function component.

> The `use()` method applies to the `Model.use()` hook path only. A [`Component`](/docs/api/component) rendered as JSX never calls it.

### With a `mount()` method

`mount()` runs once when the owning component commits, never during server render; return a function to run on unmount. It runs for `Model.use()`, `<Component for={Class}>`, and a rendered Component - each owns its instance - and not for `Model.get()`, an instance passed to `<Component for>`, or one placed as `{instance}`. See [lifecycle hooks](/docs/api/state#lifecycle-hooks).
